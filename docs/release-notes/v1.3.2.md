# Cordum v1.3.2

Released 2026-11-25.

v1.3.2 is a security patch release. It is the v1.3.1 tag plus one fix,
cherry-picked from `main` (#603, 3a9c9e1f). It contains no other change from
`main`. See
[CHANGELOG.md](https://github.com/cordum-io/cordum/blob/v1.3.2/CHANGELOG.md),
under [v1.3.2]. For the rest of the 1.3 line, see the
[v1.3.1 notes](https://github.com/cordum-io/cordum/blob/v1.3.2/docs/release-notes/v1.3.1.md).

## Security

- **Edge evaluate no longer passes client-supplied system labels to the Safety Kernel** (#603, GHSA-j33m-mr27-pmw3). `POST /api/v1/edge/evaluate` passed request and session labels with a `_` prefix to the kernel. With `CORDUM_DELEGATION_POLICY_ENABLED=true`, the kernel read forged `_delegation.*` labels as gateway-verified delegation metadata. A caller with `jobs:write` could then change the result of rules that use `match.delegation` or a `delegation.*` predicate on `job.edge.action`. The Edge policy mapper now drops every untrusted label with a `_` prefix, which is the rule the gateway already applies on job submit.

## Who is affected

Releases 1.0.0 through 1.3.1, and only when both of these are true:

- `CORDUM_DELEGATION_POLICY_ENABLED=true` is set on the Safety Kernel. The default is off.
- A policy bundle has delegation rules or `delegation.*` predicates that match `job.edge.action`.

## Upgrade notes

- No configuration change is necessary.
- Edge request and session labels with a `_` prefix no longer reach policy evaluation. Each drop increments `cordum_edge_request_labels_stripped_total{namespace="_"}`.
- If you cannot upgrade now, do not rely on delegation rules for Edge actions.

## Artifacts

- **Container images (8).** For a stable `v1.3.2` tag, the publish workflow (`.github/workflows/docker.yml`) is configured to publish each image as `1.3.2`, `1.3` and `latest`, on both `ghcr.io/cordum-io/cordum/<name>` and `docker.io/cordum/<name>`: api-gateway, scheduler, safety-kernel, workflow-engine, context-engine, mcp, dashboard and demo-quickstart-worker.
- **Helm chart:** `oci://ghcr.io/cordum-io/cordum/charts/cordum`, at the core version, published only after the published-image smoke tests succeed.
- Verify published artifacts with the [RELEASING.md verification steps](https://github.com/cordum-io/cordum/blob/main/RELEASING.md#4-verify-cosign-signatures).

## Known gaps

- **Desktop binaries are gated on a signed manifest.** Without the GPG signing key the release workflow attaches no `cordum-hook`, `cordum-claude`, `cordum-agentd` or SHA256SUMS, as for v1.3.1.
- **This release is cut from the `release/1.3` branch, not from `main`.** `main` has the same fix, together with changes that are not in the 1.3 line.
