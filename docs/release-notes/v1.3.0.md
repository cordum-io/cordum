# Proposed Cordum v1.3.0 (unreleased)

These are draft notes for the next core release. The version and release date
remain proposals; these notes do not create a tag or establish that any new
release artifacts have been published. They summarize main after the v1.2.0
tag (3244b541, 2026-07-21), with selected history from v1.1.0 to v1.2.0.
Each item below names its range. See
[CHANGELOG.md](https://github.com/cordum-io/cordum/blob/main/CHANGELOG.md),
under [Unreleased] and [v1.2.0].

The [v1.2.0 GitHub Release](https://github.com/cordum-io/cordum/releases/tag/v1.2.0)
was published on 2026-10-17. Its original dashboard image publication gap was
repaired on 2026-10-27 from the exact tagged source. The version-pinned
dashboard now passes anonymous native pull, signature and health checks on
both architectures, and an isolated fresh Helm 1.2.0 installation passed.
The recovered image's signatures use the
[recovery branch identity](https://github.com/cordum-io/cordum/blob/a0350ab9a47430ef4c03bd242815dd4911016210/.github/workflows/recover-dashboard-v1.2.0.yml),
which must be supplied explicitly when verifying that image.

## Highlights

Since v1.2.0:

- **CAP-PRODUCTION profile** (#394). A new opt-in `CORDUM_CAP_PROFILE=production` mode for the scheduler. In it, the scheduler fails closed on exact-wire trust, replay, attempt fencing, durable effects and sealed structured resources. The API gateway and workflow engine are not production-ready. They refuse to start with `production`.
- **CAP v2.17.0** (#404, #408, #441). The root and `sdk` modules move to the published CAP v2.17.0.
- **Dependency refresh** (#400, #401, #402, #441, c7d33432, #467, #474). Go modules, including grpc 1.84.0, nats-server 2.15.1, otel 1.47.0 and x/crypto 0.58.0. Dashboard packages, including react 19.3 and vite 8.3. The TypeScript and Python SDK clients are regenerated (#441, #403).
- **CI credential masking** (#431). Generated CI credentials are masked in the nightly, e2e and smoke workflows.
- **Helm publication gate** (#493). The chart is published only after published-image smoke tests succeed.

From v1.1.0 to v1.2.0:

- **Authenticated worker sessions** (#389, #390). Worker sessions require a P-256 worker proof bound to a scheduler challenge, and an Ed25519 session issued by the scheduler.
- **Control-plane service tokens** (#341). Peer schedulers admit internal result and cancel broadcasts under `enforce`. Session tokens are bound to the identity in the packet.
- **GitHub Copilot governance.** It uses Cordum's MCP server (#370), agent hooks through `cordum-hook copilot` (#371), and an LLM-proxy ingest endpoint that is off by default (#372).
- **Edge.**
  - Edge approvals appear on the dashboard Approvals page (#342).
  - Bash, Grep and Glob arguments go through secret-path detection (#363).
  - `cordumctl edge doctor` reports the effective fail-open or fail-closed posture (#391).
- **Security fixes** (#362, #336, #335). MCP identity and approval lookups are scoped to the tenant. Delegation, throttle and policy-verifier paths that failed open now fail closed. The safety kernel fails closed when it cannot read output.

## Upgrade notes

- **`CORDUM_CAP_PROFILE`** (#394) is opt-in.
  - An unset, empty or whitespace-only value means `compat`, which is the default.
  - The value is trimmed and lowercased; anything that does not then equal `compat` or `production` refuses to boot.
  - See [docs/cap_production_profile.md](https://github.com/cordum-io/cordum/blob/main/docs/cap_production_profile.md).
- **Worker handshake** (#389). The shipped defaults are `CORDUM_SDK_HANDSHAKE=off` and `CORDUM_HEARTBEAT_MODE=authority`.
  - Keep them until every worker proof key is enrolled.
  - Then roll out to `warn`+`warn`, then to `enforce`+`telemetry`.
  - Active handshake requires `WORKER_ATTESTATION=off`.
  - See [docs/sdk/handshake.md](https://github.com/cordum-io/cordum/blob/main/docs/sdk/handshake.md).
- **`enforce`** (#341). Put the same Ed25519 signing key on the scheduler, api-gateway and workflow-engine before you enable `enforce`.
- **`CORDUM_SDK_HANDSHAKE` typos** (#341). A misspelled value, such as `enforse`, now refuses to boot. Previously it fell back to warn silently.
- **Telemetry** (#363). The default `local_only` mode now sends at most one install ping and one first-use ping. Set `CORDUM_TELEMETRY_MODE=off` for zero outbound calls.
- **Source builds** need Go 1.26.3 or later (#380). go.mod requests the go1.26.5 toolchain (#362).

## Fixed

- **Legacy MCP approval-required responses** (#491). Approval expiry is decoded as Unix microseconds so legacy HTTP MCP approval responses encode successfully and report the approval TTL.
- **Memory pointer reads under the `compat` profile** (832236ad). `GET /api/v1/memory?key=|?ptr=` returned 400 under the default profile. This affected only the GHCR `:main` and `:sha-*` images built between #394 and 832236ad. No tagged release contained it.
- **The nightly soak memory-drift gate** no longer fails on integer truncation and warm-up heap growth (d2f6ec2b).

## Planned artifacts (not published by these notes)

- **Container images (8).** After approval of a stable release tag and successful image jobs, the publish workflow is configured to publish each image at the approved full version, major/minor alias and `latest`, on both `ghcr.io/cordum-io/cordum/<name>` and `docker.io/cordum/<name>`. The proposed aliases are `1.3.0` and `1.3`; their existence is not claimed here. The names are:
  - api-gateway
  - scheduler
  - safety-kernel
  - workflow-engine
  - context-engine
  - mcp
  - dashboard
  - demo-quickstart-worker
- **Supply-chain metadata.** Image jobs are configured to produce an SBOM, build provenance and a cosign keyless signature. Verify the actual published artifacts before declaring the release complete.
  - Current signing uses Sigstore bundle v0.3 signatures stored as OCI referrers, so verification needs a compatible cosign release.
  - Follow the [RELEASING.md verification steps](https://github.com/cordum-io/cordum/blob/main/RELEASING.md#4-verify-cosign-signatures).
- **Helm chart:** `oci://ghcr.io/cordum-io/cordum/charts/cordum`, using the approved core version. Publication waits for successful image smoke tests; no `1.3.0` chart publication is claimed here.

## Known gaps

- **Desktop binaries remain gated.** The canonical release workflow refuses to attach `cordum-hook`, `cordum-claude`, `cordum-agentd` and SHA256SUMS without a GPG-signed manifest. The published v1.2.0 release has no binary assets. Signing-key readiness and the next release's actual assets must be checked at publication time; these draft notes do not assert the current secret configuration. See [tools/keys/README.md](https://github.com/cordum-io/cordum/blob/main/tools/keys/README.md).
- **`:latest` remains mixed as of 2026-10-27.** The original v1.2.0 run left the 1.2.0 control-plane images alongside the 1.1.0 dashboard image under `:latest`. The dashboard `1.2.0` recovery deliberately preserved floating aliases. Use the repaired version-pinned release for verification; do not infer a future alias promotion from these notes.
