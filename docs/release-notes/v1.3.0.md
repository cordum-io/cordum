# Cordum v1.3.0

Released 2026-11-11.

These notes summarize first-parent history on `main` from the v1.2.0 tag
(3244b541, 2026-07-21) to the v1.3.0 tag, with selected history from v1.1.0 to
v1.2.0. Each item below names its range. See
[CHANGELOG.md](https://github.com/cordum-io/cordum/blob/main/CHANGELOG.md),
under [v1.3.0] and [v1.2.0].

The [v1.2.0 GitHub Release](https://github.com/cordum-io/cordum/releases/tag/v1.2.0)
was published on 2026-10-17. Its original dashboard image publication gap was
repaired on 2026-10-27 from the exact tagged source. The version-pinned
dashboard now passes anonymous native pull, signature and health checks on
both architectures, and an isolated fresh Helm 1.2.0 installation passed.
The recovered image's signatures use the
[recovery branch identity](https://github.com/cordum-io/cordum/blob/a0350ab9a47430ef4c03bd242815dd4911016210/.github/workflows/recover-dashboard-v1.2.0.yml),
which must be supplied explicitly when verifying that image.

## Highlights

Since v1.2.0:

- **CAP-PRODUCTION profile** (#394). A new opt-in `CORDUM_CAP_PROFILE=production` mode for the scheduler. In it, the scheduler fails closed on exact-wire trust, replay, attempt fencing, durable effects and sealed structured resources. The API gateway and workflow engine are not production-ready. They refuse to start with `production`.
- **CAP v2.17.0** (#404, #408, #441). The root and `sdk` modules move to the published CAP v2.17.0.
- **Dependency refresh** (#400, #401, #402, #441, c7d33432, #467, #474, #482, #483, #484, #497, #499, #524). Go modules, including grpc 1.85.0, nats-server 2.15.2, nats.go 1.55.0, go-jose 4.1.9, crewjam/saml 0.6.1, otel 1.47.0 and x/crypto 0.58.0. Dashboard packages, including react 19.3, vite 8.3 and @hookform/resolvers 7, plus 14 patched transitive packages pinned through pnpm `overrides`. The TypeScript and Python SDK clients are regenerated (#441, #403).
- **Dashboard Zod 4 and dependency security refresh** (#494). Typed forms move to Zod 4. Vulnerable transitive dependencies are refreshed: fast-uri 3.1.9, DOMPurify consolidated on 3.4.17, undici 7.30.1, vitest 4.1.12 and qs 6.16.1.
- **CI credential masking** (#431, #487). Generated CI credentials are masked in the nightly, e2e and smoke workflows, and runtime-minted production-gate credentials are masked before first use.
- **MCP approvals fail closed and resume exactly once** (#524). A tool that requires approval is refused with `-32097` when no approval gate is wired, instead of running ungated. `cordum_create_workflow` on the gateway's HTTP MCP endpoint creates the workflow after a distinct operator approves. With `mcp.policy_gate_enabled=true`, approvals are bound to the real policy pre-event, and a resumed call executes exactly once.
- **Worker-to-agent links are resolved inside the worker's tenant** (#524). The scheduler's handshake trust resolver and the agent resolver look a link up in the tenant of the worker's credential. This is slice 1 of 3; links are still written to the legacy global key.
- **Helm publication gate** (#493). The chart is published only after published-image smoke tests succeed.

From v1.1.0 to v1.2.0:

- **Authenticated worker sessions** (#389, #390). Worker sessions require a P-256 worker proof bound to a scheduler challenge, and an Ed25519 session issued by the scheduler.
- **Control-plane service tokens** (#341). Peer schedulers admit internal result and cancel broadcasts under `enforce`. Session tokens are bound to the identity in the packet.
- **GitHub Copilot governance.** It uses Cordum's MCP server (#370), agent hooks through `cordum-hook copilot` (#371), and an LLM-proxy ingest endpoint that is off by default (#372).
- **Edge.**
  - Edge approvals appear on the dashboard Approvals page (#342).
  - Bash, Grep and Glob arguments go through secret-path detection (#363).
  - `cordumctl edge doctor` reports the effective fail-open or fail-closed posture (#391).
- **Security fixes** (#362, #336, #335). MCP identity and approval lookups are scoped to the tenant. Delegation, throttle and policy-verifier paths that failed open now fail closed. The safety kernel fails closed when it cannot read output.

## Upgrade notes

- **`CORDUM_CAP_PROFILE`** (#394) is opt-in.
  - An unset, empty or whitespace-only value means `compat`, which is the default.
  - The value is trimmed and lowercased; anything that does not then equal `compat` or `production` refuses to boot.
  - See [docs/cap_production_profile.md](https://github.com/cordum-io/cordum/blob/main/docs/cap_production_profile.md).
- **Worker handshake** (#389). The shipped defaults are `CORDUM_SDK_HANDSHAKE=off` and `CORDUM_HEARTBEAT_MODE=authority`.
  - Keep them until every worker's proof key is enrolled.
  - Then roll out to `warn`+`warn`, then to `enforce`+`telemetry`.
  - Active handshake requires `WORKER_ATTESTATION=off`.
  - See [docs/sdk/handshake.md](https://github.com/cordum-io/cordum/blob/main/docs/sdk/handshake.md).
- **`enforce`** (#341). Put the same Ed25519 signing key on the scheduler, api-gateway and workflow-engine before you enable `enforce`.
- **`CORDUM_SDK_HANDSHAKE` typos** (#341). A misspelled value, such as `enforse`, now refuses to boot. Previously it fell back to warn silently.
- **Telemetry** (#363). The default `local_only` mode now sends at most one install ping and one first-use ping. Set `CORDUM_TELEMETRY_MODE=off` for zero outbound calls.
- **Source builds** need Go 1.26.3 or later (#380). go.mod requests the go1.26.5 toolchain (#362).
- **Standalone `cordum-mcp`** (#524). The standalone binary (stdio and HTTP) wires no approval gate, so its 7 mutating tools now return `-32097` instead of executing. Use the API gateway's MCP endpoint for approval-gated tools.
- **Policy-gate MCP approvals** (#524). With `mcp.policy_gate_enabled=true`, the consumed Edge approval is the only resume authority. Approving the legacy MCP approval record no longer resumes a call.
- **Worker audit labels** (#524). A worker with no cached credential tenant gets no store-link label, so its jobs record `agent_id=unlinked` in audit metadata.
- **MCP approval `retry_hint`** (#496). On the legacy approval path the -32099 `retry_hint` is `retry_with_same_args`: approve, then retry with byte-identical arguments. It is `retry_with_approval_ref` only when an Edge `approval_ref` was minted.

## Fixed

- **HTTP MCP approval-required tools on deployed gateways** (#496). Deployed gateways always build an Edge store. With `mcp.policy_gate_enabled=false` (the default), approval-required HTTP MCP tool calls failed with `-32096 approval_store_unavailable`. They now return `-32099`, with the legacy MCP approval store as the sole approval authority. Wherever an Edge approval mint is attempted, an Edge store outage still fails closed with -32096.
- **Policy-gate MCP approvals** (#524). With `mcp.policy_gate_enabled=true`, every approval-required call failed with `-32096` because the approval was bound to an event id that named no stored event. Approvals now bind to the `mcp.tool.pre` event.
- **MCP policy snapshot** (#524). Reading the snapshot no longer lists every workflow override bundle; it is one config read.
- **Legacy MCP approval-required responses** (#491). Approval expiry is decoded as Unix microseconds so legacy HTTP MCP approval responses encode successfully and report the approval TTL.
- **Memory pointer reads under the `compat` profile** (832236ad). `GET /api/v1/memory?key=|?ptr=` returned 400 under the default profile. This affected only the GHCR `:main` and `:sha-*` images built between #394 and 832236ad. No tagged release contained it.
- **The nightly soak memory-drift gate** no longer fails on integer truncation and warm-up heap growth (d2f6ec2b).

## Artifacts

- **Container images (8).** For a stable `v1.3.0` tag, the publish workflow (`.github/workflows/docker.yml`) is configured to publish each image as `1.3.0`, `1.3` and `latest`, on both `ghcr.io/cordum-io/cordum/<name>` and `docker.io/cordum/<name>`. The names are:
  - api-gateway
  - scheduler
  - safety-kernel
  - workflow-engine
  - context-engine
  - mcp
  - dashboard
  - demo-quickstart-worker
- **Supply-chain metadata.** Image jobs are configured to produce an SBOM, build provenance and a cosign keyless signature for each image. Verify the published artifacts before relying on them.
  - Current signing uses Sigstore bundle v0.3 signatures stored as OCI referrers, so verification needs a compatible cosign release.
  - Follow the [RELEASING.md verification steps](https://github.com/cordum-io/cordum/blob/main/RELEASING.md#4-verify-cosign-signatures).
- **Helm chart:** `oci://ghcr.io/cordum-io/cordum/charts/cordum`, at the core version. The chart job runs only after the published-image smoke tests succeed (#493).

## Known gaps

- **Desktop binaries are gated on a signed manifest.** The canonical release workflow requires a GPG-signed manifest. Without one, it fails before `gh release create`: it neither creates a Release nor attaches `cordum-hook`, `cordum-claude`, `cordum-agentd` and SHA256SUMS. The published v1.2.0 release has no binary assets. For the signing-key status, see [tools/keys/README.md](https://github.com/cordum-io/cordum/blob/main/tools/keys/README.md).
- **`:latest` was mixed during the v1.2.0 line.** From 2026-07-21, the original v1.2.0 run left the 1.2.0 control-plane images alongside the 1.1.0 dashboard image under `:latest`. The 2026-10-27 dashboard `1.2.0` recovery deliberately preserved floating aliases. Pin images by version or digest rather than relying on `:latest`.
