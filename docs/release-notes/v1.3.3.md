# Cordum v1.3.3

Released 2026-11-26.

v1.3.3 is a security patch release. It is the v1.3.2 tag plus the fixes of
#605 (989dcafa4 on `main`) and the label handling of #590, adapted to the 1.3
line. It contains no other change from `main`. See
[CHANGELOG.md](https://github.com/cordum-io/cordum/blob/v1.3.3/CHANGELOG.md),
under [v1.3.3]. For the rest of the 1.3 line, see the
[v1.3.2 notes](https://github.com/cordum-io/cordum/blob/v1.3.3/docs/release-notes/v1.3.2.md).

**Upgrade is strongly recommended for every deployment.** A security advisory
with the details follows this release.

## Security

The Safety Kernel reads some request fields as server-side facts. These fixes
make each of them come from a server-side source only.

- **Safety Kernel: client labels no longer reduce the rules of a job** (#605). The kernel chose the rule section of a job from its topic and from its MCP labels (`mcp.server`, `mcp_tool`, `mcpAction` and the other alias names). Labels come from the client. A job that declares an MCP call is now checked against the same rules as a job without the labels, plus the rules with `match.mcp` lists, in the order the policy lists them.
- **Edge evaluate: labels the kernel reads by name stay server-owned** (#605). The Edge policy mapper now also drops `agent_id`, `secrets_present`, the `mcp` alias names and the workflow and job scope labels (`workflow`, `workflow_id`, `workflow_run_id`, `workflow.*`, `run_id`, `step_id`, `job_id`, `job.id`, `session_id`) from request and session labels. The gateway sets `agent_id` from the worker link of the principal, as job submit does.
- **Job submit: `_source` follows the worker link** (#605). HTTP and gRPC submit set `_source=pack` whenever the request carried a `pack_id`. `pack_id` is a client field. The label is now `pack` only when a principal with a worker link sends a `pack_id`. Every other caller gets `api`.

- **Job submit and workflow steps: labels that only Cordum services write** (#590). HTTP and gRPC job submit kept client labels with these names: `approval_*`, `gate_type`, `cordum.bus_msg_id`, `policy.attachment_id` and the workflow context (`workflow_id`, `run_id`, `step_id`, `workflow`, `workflow_run_id`, `workflow.*`). The scheduler, the approval code and the Safety Kernel act on these labels. Job submit now drops them and logs their names. The workflow engine drops them, and the `_` system labels, from the route labels of a step.

## Who is affected

Releases 1.0.0 through 1.3.2. The first and the last fix apply to every
deployment that accepts jobs from callers that are not fully trusted. The other two apply when
policy rules use `agent_risk_tiers`, `agent_data_classifications`,
`secrets_present`, `match.mcp`, workflow or job tier overrides on
`job.edge.action`, or the `_source` label.

## Upgrade notes

- Most deployments need no configuration change. Check the items below: some policies, job labels, workflow route labels and pack workers need one.
- A job with MCP labels is now checked against the input rules too. A policy that relied on MCP labels to reach only the `match.mcp` rules must add a rule for the topic.
- Edge: the `workflow_run_id` and `job_id` of a session are stored as evidence for correlation. They no longer select workflow or job override rules. Session-scoped overrides through `policy.attachment_id` are unchanged.
- Edge: `agent_risk_tiers` and `agent_data_classifications` rules now apply to Edge actions of a principal that has a worker link.
- Edge: each dropped label increments `cordum_edge_request_labels_stripped_total`. New `namespace` values: `agent_id`, `secrets_present`, `workflow`, `job`.
- Job submit drops client labels named `approval_*`, `gate_type`, `cordum.bus_msg_id`, `policy.attachment_id`, `workflow_id`, `run_id`, `step_id`, `workflow`, `workflow_run_id` and `workflow.*`. If you use one of these names for your own job labels, use a different name. The gateway logs `dropped server-owned labels from client job input` with the names.
- Workflow definitions: a route label with one of these names, or with a `_` prefix, is no longer copied to the job of the step. The workflow engine logs `workflow route label dropped`.
- A pack worker that submits with a principal that has no worker link is now `_source=api`. Rules that allow only `pack` or `workflow` sources (for example `b2b-pack-allow` in `config/safety.yaml`) no longer match its jobs. To keep `_source=pack`, link the worker to an agent identity: issue its worker credential with an `agent_id` (`POST /api/v1/workers/credentials`), and submit with a principal that is the worker ID.

## Artifacts

- **Container images (8).** For a stable `v1.3.3` tag, the publish workflow (`.github/workflows/docker.yml`) is configured to publish each image as `1.3.3`, `1.3` and `latest`, on both `ghcr.io/cordum-io/cordum/<name>` and `docker.io/cordum/<name>`: api-gateway, scheduler, safety-kernel, workflow-engine, context-engine, mcp, dashboard and demo-quickstart-worker.

- Verify published artifacts with the [RELEASING.md verification steps](https://github.com/cordum-io/cordum/blob/main/RELEASING.md#4-verify-cosign-signatures).

## Known gaps

- **Desktop binaries are gated on a signed manifest.** Without the GPG signing key the release workflow attaches no `cordum-hook`, `cordum-claude`, `cordum-agentd` or SHA256SUMS, as for v1.3.2.
- **This release is cut from the `release/1.3` branch, not from `main`.** `main` has the same fixes, together with changes that are not in the 1.3 line. The 1.3 line does not have all the hardening that `main` has. The next release from `main` will include it.
